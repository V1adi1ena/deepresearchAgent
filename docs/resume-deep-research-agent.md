## 使用前提（重要）

本稿是目标文案，不代表当前已实现或已验证。机制按 L1–L3 逐项验收，入口、指标和运行记录分别对应 L0、L0.5、L4；不要求为填写简历完成所有可选量化实验。规则：

1. 每条 bullet 只在对应阶段验收通过后使用；未完成的不要投。
2. `⟨…⟩` 是占位符，必须换成**实测真数**后使用；不许填估计值、更不许编。填不出就整段删掉该数字，句子照样通顺。
3. 数字及其从句都是可选补充；没有测量时删除，不影响保留已验收的机制。测试通过数不能替代行为覆盖，模型效果不能用 mock 或回放结果代替。
4. “开关控制模块接入”需要离线调用验证；真实模型消融不属于本轮必做项，未跑对照不写消融收益。

## 版本 A（推荐，4 条，投后端 / AI 应用实习通用）

### Deep Research Agent｜个人项目
**Python · asyncio · SQLite · NumPy · Sentence Transformers · pytest**

面向复杂研究任务的多智能体系统：将问题拆解为 DAG 子任务图，按层并发调度检索 / 阅读 / 计算子 Agent 并合成带引用报告；针对长链路研究中的上下文增长与证据漂移，设计跨 Agent 记忆复用、分级压缩与 Red-Blue 证据审查。

- **异步编排与容错**：基于 asyncio 与 Semaphore 实现 DAG 分层并发调度，每层结束发布结果，并由代码按依赖关系向下游注入上下文；以 9 状态状态机管理规划、执行、合成与重规划，区分有界重试与方案重规划，复用成功结果并纳入最终合成；在全局期限内预留收尾预算，支持部分报告或已收集结果返回，标记未完成子任务。离线回归覆盖部分成功、全部失败、阶段超时与全局超时，pytest ⟨N⟩ 例通过。

- **超时与取消边界**：针对协程取消后底层请求仍可能执行的问题，隔离并记录晚到结果，阻止其回流证据链；验证信号量控制下的调度任务峰值不超过配置值 ⟨M⟩，分别记录调度任务与尚未结束的外部请求。

- **共享记忆与上下文压缩**：基于 SQLite 与 NumPy 实现跨 Agent 共享记忆，支持写入、语义检索与会话隔离，压缩时保留"任务—来源—摘录"关联以维持结论可追溯；在固定文档与干扰文本下对照直接截断、相关性筛选与 TextRank 关键句提取，证据保留率分别为 ⟨a% / b% / c%⟩，压缩比 ⟨d×⟩。

- **证据审查与评测口径**：Red 输出带定位与证据的结构化问题，Blue 补检后定向修复或删除无依据结论，保留修改前后内容、来源及版本，以轮数和调用预算限制无效迭代；在标注样本上实测发现率 ⟨p%⟩、修复率 ⟨q%⟩、误修改率 ⟨r%⟩。限定参考事实匹配指标的适用范围，加入错值、实体错配和否定反例，区分引用可追溯与来源内容支持，并验证模块开关控制实际执行路径。

## 可选数字的测量口径

未做对照时删除相应数字从句。所有比例同时记录分子、分母和问题级结果；分母为零时记为不适用，不填 0%。

| 占位符 | 怎么得到 | 调用与记录要求 | 是否必填 |
| --- | --- | --- | --- |
| ⟨N⟩ pytest 例数 | 采用实际通过记录，并说明覆盖的关键行为 | 离线执行，隔离数据库和输出；不以数量作为验收 | 可选 |
| ⟨M⟩ 调度任务并发上限 | 配置值 + mock 条件下实际调度任务峰值 | 单列未结束的外部请求，不将协程上限冒充底层请求上限 | 可选 |
| ⟨a/b/c%⟩ 证据保留率 | 固定文档、标注证据和干扰内容；三种策略保留的标注证据数 / 全部标注证据数，在同一预算下比较 | 可用本地 embedding，不需要付费 LLM；记录样本规模和匹配规则 | 可选 |
| ⟨d×⟩ 压缩比 | 压缩前 token / 压缩后 token，采用同一 tokenizer；若用字符，明确标注字符压缩比 | 与保留率共同记录，不能混用字符与 token | 可选 |
| ⟨p/q/r%⟩ 检出 / 修复 / 误修改率 | 检出率 = 正确发现的植入错误数 / 全部植入错误数；修复率 = 实际修正的植入错误数 / 全部植入错误数；误修改率 = 被改坏的原本正确项数 / 原本正确项总数 | 样本同时含错误项和正确对照项；真实审查与补检按用量计费，回放只验证流程 | 可选 |
| 完成率、调用数、耗时 | L4 的 5 题链路检查与现有题库 3–5 题对照分别记录；有证据、回答问题、引用支持的成功判据预先明确 | 保存模型、配置、逐题结果及真实用量，不预先承诺工时或费用 | 可选 |

## 措辞上的几个决定

- 不写"原文保留"。实际 L3 是层级摘要，写了会被 README 与代码对上。
- 不写“成功率提升 X%”等效果数字，除非有对应基线、统一设置和实际记录。保留率、检出率等也需要明确口径与对照，不能仅因数字更局部就自动认定因果或泛化能力。
- 不写"生产环境""上线""用户量"。个人项目就标个人项目。
- 写"自建评测集"时要标"自建"，不要让人误以为用了公开 benchmark。
- 技能栏只放面试能答的：Sentence Transformers 在确认真的加载到模型（而非降级为随机向量）之前不要写。
- 项目描述使用“针对……设计……”说明设计意图；效果使用实际验证结果表述，未量化时保留已完成的机制和行为验证。
