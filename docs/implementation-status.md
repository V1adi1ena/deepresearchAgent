# 求职版本实施与验证记录

## 已实施

- DAG 每层结束发布结果；按已校验的依赖向下游提示词注入上下文，失败依赖阻断执行。
- 重规划保留成功结果并纳入最终合成；允许新计划引用已完成任务，不重跑它们；禁止以相同成功任务 ID 偷换任务定义。
- 区分临时连接故障重试与方案重规划，限制次数；全局期限预留收尾预算，无预算时返回已收集结果及未完成任务。
- 将同步模型调用移出事件循环；将剩余期限传给 SDK；取消后丢弃晚到结果，超时 Agent 不回池复用。协程取消仍不等于立即终止底层请求。
- 使用 session/run/task 作用域写入研究记忆；将相关记忆接入研究 Agent。相似度仅用于提出重复候选，不能自动合并不同数值或否定结论。
- 在真实工具消息增长与报告合成边界接入压缩，保留工具调用 ID、消息配对和来源映射；接通记忆与压缩开关。
- Red-Blue 默认集中审查事实与无依据声明，保留其他维度可选能力；补检来源进入统一来源表，记录修改前后内容与来源。自检使用证据而非把错误原文当真值，核验失败回退。
- 对修复后的实际候选重新审查，评分与版本绑定；模型调用和轮数均受预算限制，未完成核验的候选不发布。
- 使用范围明确的 `reference_fact_match`，检查错值、实体错配及否定；统一评分字段，缺失必需字段不静默计零。语义覆盖默认不参与基准评分，随机 embedding 不能输出正式语义分数。
- 运行与测试使用独立数据库、输出和会话；报告生成后保存状态、任务摘要、事件、来源及真实 SDK 用量。无证据时不以长报告冒充完成。

## 2026-10-25 晚间：真实运行暴露问题后的修复

[用户运行的 5 题与 3 题基线原始记录](runs/20261025_203738_02ce615a/summary.json)均曾打印 `technical_chain_success=True`，但旧条件仅要求状态不是 failed 且有来源，该结果不能作为通过证据：一个基线报告正文为空；所有 DAG 记录均有真实 embedding 不可用错误；其中四个 DAG 最终只返回未完成任务提示，另一个正文截断。

修复内容：

- Windows 基础 Python 入口加载项目虚拟环境依赖，避免绕过写权限问题时遗漏 sentence-transformers；完整检查在搜索和模型调用前加载真实向量模型，失败即停止。
- 验证脚本显式指定 DeepSeek 非推理模式并分配各模块输出预算，保留其他入口的模型默认设置。参数依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。之前记录中部分调用的输出额度全部用于 reasoning，未产生报告正文。
- SDK 调用日志记录 finish_reason、输出字符数及输出预算；空正文且无工具调用、length 截断或供应商中断均作为失败处理，不主动重复付费调用。报告合成层也拒绝空/截断结果。
- 研究子任务按输出 token 预算约束摘要篇幅；合成报告优先输出结论、比较与证据缺口，引用表仅列实际引用来源。移除与有限预算冲突的长篇七节展开要求，避免依赖更大超时或接受截断来凑通过。
- 审查调用或 JSON 解析失败不再伪造 5 分与空问题列表；编排器保留原报告，标注 review_status。部分报告不进入审查；审查超时及预算耗尽不能当作审查完成。
- 每轮按优先级最多处理 1 项问题，为修复、自检和候选复核保留调用额度，未解决问题仍由复核记录反映，不宣称全部修复。完整保留最多 16,000 字符的报告和稳定来源 ID，避免仅审查/修改前 4,000 字符或仅自检前 2,000 字符；审查提示超过 34,000 字符则明确失败并保留原版本，不静默截断后认可修改。
- technical_checks 分别检查完整状态、正文、来源、任务完成、运行异常和所需审查完成；质量人工核对字段仍默认 null。
- 规划提示直接采用实际任务上限，移除“3–8 个”“无记忆时 6–10 个”与两任务配置的冲突；新增 `--question-id` 以便只复测失败题。无文本变化的修复操作不再计为成功修复。
